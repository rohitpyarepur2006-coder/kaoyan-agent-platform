# 题目录入与审核：Issue #4 第二阶段

日期：2026-10-13。基于历史版本分支，当前开发分支为`feat/question-review`。本阶段实现管理员草稿、修订、通过/驳回和审计，不实现发布或撤回；不是#4全部完成。

## 接口与权限

所有接口沿用`/api/admin/questions`，仅真实登录管理员可调用；学生403，未登录401。作者和审核人取服务端身份，不接受客户端指定。分页从0开始，每页20条。

| 接口 | 输入/输出 | 验收标准 |
| --- | --- | --- |
| GET /api/admin/questions?page=0 | 当前题目及最新编辑版本、审核状态 | 演示旧题明确标记unreviewed，不伪造审核 |
| GET /api/admin/questions/{id} | 最新编辑版本完整内容与审核元数据 | 只向管理员展示答案、解析和提示 |
| POST /api/admin/questions | 题目内容和来源登记 | 保存新逻辑题目、不可变版本与draft记录；active=false |
| PUT /api/admin/questions/{id} | 完整题目内容及expectedVersionId | 创建新版本；并发旧编辑409；不覆盖旧快照或切换可练版本 |
| GET /api/admin/questions/{id}/versions | 该题全部版本及审核元数据 | 旧版本内容仍可读 |
| POST /api/admin/questions/{id}/review | questionVersionId、status、comment | 仅最新draft可approved/rejected；已决策重复请求409；不激活题目 |
| GET /api/admin/questions/{id}/reviews | 历次审核人、意见、时间和目标版本 | 一次决策仅一条日志，按时间排序 |

题目输入使用题目专用DTO：subject、difficulty、knowledgePointId（UUID）、knowledgePointName、stem、options（恰好A—D）、correctOption、explanation、可空hintConcept/hintApproach、sourceTitle、sourceUrl、sourceLocator、license、retrievedAt（日期）、questionOrigin及可空examYear。仅修订使用expectedVersionId。

来源类别沿用完整设计的self_authored/authorized_past/simulated；只有authorized_past要求年份，其他类别不得冒填年份。来源链接允许HTTP(S)或项目内/references/路径。题干最大2000、每个选项1000、解析4000、每级提示2000字符，与快照存储上限一致。

替换原来仅返回501的题目录入占位DTO；当前只支持单个知识点，不能传原占位knowledgePointIds/sourceChunkIds。SourceChunk尚未实现，本阶段登记可追溯来源字段，未来与资料负责人确定关联后再扩展；不接受虚构的资料块编号。

## 数据与依赖

- 依赖#6的QuestionVersion不可变内容快照。
- Question保留当前目录投影，新题inactive，已有题修订不改投影；QuestionEditorial保存最新编辑版本指针。
- QuestionReviewState逐版本保存draft/approved/rejected、创建人、日期、来源权限和题目来源类别；QuestionReviewEvent追加保存真实审核操作。
- 修订和审核锁定同一逻辑题目行，检查版本再写入，避免两个管理员覆盖编辑或重复决策。数据库迁移和外键等正式约束由#5统一提供。
- 学生题池不增加新草稿、驳回或已审核未发布题目；原有12道待复核演示题仍属于既有演示环境，不能称为正式审核题池。
- 资料、招生和共享发布API保持原有占位行为；审核通过不调用Python、不激活release、不自动上线。
- 前端提供管理员表单、版本历史、审核意见及通过/驳回操作；角色仍由服务端控制，公开注册不提供管理员入口或角色升级。
- 管理员账号须由认证负责人按团队流程配置；本阶段不提供初始化管理员脚本、固定密码或公开提权接口。自动测试只在隔离H2数据库创建管理员。
- 知识点目录目前从演示题推导，页面只能选择当前目录或保留已有题目的知识点；独立知识点维护与批量导入不在本阶段范围。API登记UUID及名称，不等于完成了外部知识目录的审核关联。
- 当前允许管理员审核自己录入的题目；若团队要求录入人与审核人分离，需要另行明确规则并增加校验，不能把代码审查批准等同于逐题内容审核。

## 本地验证方式

后端从backend目录执行`./mvnw.cmd -B test`。管理员页面检查采用模拟API，不需要启动Java或Python，也不修改真实账号或题库。从仓库根目录执行：

```powershell
$env:NODE_PATH=(Resolve-Path ".\.cache\browser-tools\node_modules").Path
$env:CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
node scripts/question-review-browser-check.cjs .cache/question-review-browser-new.json
```

需要事先安装Playwright；可用`npm.cmd install --prefix .\.cache\browser-tools playwright --ignore-scripts`。报告文件名必须未存在。页面源码与Spring静态资源同步提交，正式数据库在#5迁移完成前不作升级验收。

## 验收

1. 新草稿与审核通过后均不出现在学生目录、批次、收藏题池；人工发布尚未实现。
2. 修订现有演示题后，旧批次、当前学生目录及原解析保持原版本。
3. 非管理员、伪造作者、缺来源、非法选项、年份类别不符、过期编辑、其他题目的版本均被拒绝。
4. 批准/驳回记录真实审核人和时间；重复审核不重复写日志；驳回后修订生成新draft，旧记录保留。
5. 表单能够创建、读取、修订和审核；题目文字以textContent等安全方式显示；退出后清理管理内容，旧请求不能在新账号下显示。
6. Java测试验证实际权限、事务和持久化；浏览器检查单独注明真实或模拟接口范围，不冒充发布/迁移验收。

现有12道题的人工内容审核、正式发布、撤回统计和PostgreSQL迁移仍是后续工作。自动化测试中的管理员与批准记录只存在于隔离测试数据，不代表团队人工审核。
