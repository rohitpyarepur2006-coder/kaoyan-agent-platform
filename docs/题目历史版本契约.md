# 题目历史版本：Issue #4 第一阶段

后续状态：第二阶段已在独立分支实现题目录入、修订与审核，见[题目录入与审核契约](题目录入与审核契约.md)。以下保留第一阶段的交付边界；其中管理接口501的说明仅针对第一阶段。

日期：2026-10-13。基于PR #3的刷题演示闭环，分支为`feat/question-versioning`。本阶段实现内容快照与固定版本读取；题目审核、发布、版本撤回和正式数据库迁移尚未完成。

## 问题与实现范围

原实现保存了`questionVersionId`，但批次题目、提示、判分和作答解析仍查询当前`Question`。修改题干或标准答案后，旧批次可能展示新内容、无法提交，旧作答可能显示新解析。

新增`QuestionVersion`保存独立内容；批次和作答通过`questionId + questionVersionId`查找原版本。当前`Question`暂保留现有结构，作为当前目录的投影，避免在本阶段提前实现共享资料发布。

本阶段没有新增HTTP管理能力，管理接口仍为501；学生端URL和JSON结构、公共枚举、认证、Python契约不变。页面与Python无需修改。测试中的内部版本切换夹具不代表用户已经可以通过管理员页面编辑或发布题目。

## 数据与内部接口

| 对象 | 字段或方法 | 约束 |
| --- | --- | --- |
| Question | id、versionId及当前目录内容 | id为稳定UUID，versionId指向当前版本 |
| QuestionVersion | id为版本UUID，questionId、科目、难度、知识点、题干、A—D选项、标准答案、解析、两级提示、来源标题/URL/定位 | 内容追加保存；不包含审核通过标记，不因保存快照获得正式发布资格 |
| QuestionVersionStore.record | 接受完整Question，保存其内容快照 | 相同ID和内容幂等；相同ID不同内容返回409 QUESTION_VERSION_IMMUTABLE；使用persist而非merge |
| QuestionVersionStore.require | questionId、versionId；返回脱离持久化上下文的内容副本 | 缺失或所属题目不符返回409 QUESTION_VERSION_UNAVAILABLE；不回退当前题目 |
| PracticeSessionItem | questionId、questionVersionId | 项目读取、草稿校验、提示和判分绑定相同版本 |
| PracticeAttempt | questionId、questionVersionId及判分结果 | 历史详情、列表及幂等重放读取相同版本的解析与来源 |

历史实体无公开setter，列不可通过ORM更新，Repository只暴露读取方法。数据库管理员直接SQL修改不在此应用层保护范围；数据库约束及迁移由#5落实。内部内容副本不能保存回当前Question，也不能原样返回给学生。

## 外部接口行为

| 接口 | 版本处理 | 验收 |
| --- | --- | --- |
| POST /api/practice-sessions | 先检查选中题目的快照存在，再保存批次和项目 | 缺失快照返回409且不创建部分批次 |
| GET /api/practice-sessions/{id}/items/{itemId} | 读取项目绑定版本 | 新版本不改变旧题干和选项；未答不含答案或解析 |
| PUT /api/practice-sessions/{id}/progress | 对项目绑定版本校验答案草稿 | 切换当前版本不阻碍旧批次续做；现有revision规则保留 |
| POST /api/practice-sessions/{id}/items/{itemId}/hints | 读取项目绑定版本的提示 | 提示内容及辅助记录不随当前版本切换 |
| POST /api/attempts（含批次） | 先检查账号与项目归属，再校验输入版本是否等于项目版本 | 可提交有效旧批次；不能把新版本强塞进旧项目 |
| POST /api/attempts（无批次） | 只接受当前可练题目的当前版本 | 过期版本返回409 QUESTION_VERSION_CHANGED |
| GET /api/attempts及/{id} | 读取作答绑定版本 | 已完成后再切换版本仍返回原解析、来源和版本编号 |

目前保留原有逻辑题目active检查和项目availability检查；本阶段没有版本级撤回API、撤回后统计重算或正式发布资格筛选，不能据此关闭#4。

## 开发数据初始化与限制

`PracticeDemoData`先运行，`QuestionVersionBootstrap`随后在事务中运行。初始化读取当前题目及已有快照，对所有已有批次项目和作答的版本归属做预检，再为缺失的当前快照保存内容；重复启动不重复插入。

如果某条旧记录引用的版本既不在快照表，也不等于可恢复的当前题目版本，启动失败并报告版本ID；必须恢复真实内容，不能用当前答案冒充旧版本。已有快照与当前同版本内容不一致时同样拒绝覆盖。首次建立快照前若有人在不改版本号的情况下改过旧题，程序无法恢复被覆盖内容，需人工核实或从备份恢复。

这只是当前H2/Hibernate开发方式的过渡初始化，不是Flyway或PostgreSQL升级验收。#5完成前，不对正式数据库运行本分支做升级；已有本地数据也应先备份并在副本验证。初始化不为12道演示题伪造人工审核记录。

## 第一阶段验收

1. v1题目答案为B，创建批次后切换到答案为A的v2；旧批次仍显示v1题干和提示、可恢复草稿，选B判对；新批次使用v2，选B判错。
2. 完成v1作答后再切换v2，历史详情、列表、已答项目及相同请求重放均返回v1解析、来源和结果。
3. 不带批次提交过期版本、给旧项目提交新版本、跨账号访问旧项目均被拒绝；当前无批次作答仍可完成。
4. 同内容重复保存不新增版本，同版本号改内容被拒绝；不同题目不能互换版本。
5. 缺少快照时不创建部分批次；可恢复的旧数据保留原ID，重复初始化不重复插入；缺失的历史批次或历史作答版本使预检失败。
